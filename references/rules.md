# 记忆维护规则与踩坑（memory-daily-digest 参考）

## 一、为什么分层

每轮对话都会把「常驻文件」整份注入上下文并计费，所以：

- 常驻层（AGENTS/SOUL/USER/TOOLS/HEARTBEAT/MEMORY）只放**能改变行为**的短结论和指针
- 日记层随便写多细都行，因为它只在需要时被 read
- 摘要层是折中：够短能常读，够全能定位

判断一条内容该放哪层，问一句：**这条每轮都要看到吗？** 是→常驻；否→日记或知识库，常驻只留指针。

## 二、指针体系

- 指针 = 「细则见 X」这类文件级指向。**文件级指针天然免疫内容变更**（条文改了，指针仍指向真相）。
- 会腐烂的是「索引行里复述了旧内容」——索引描述变了、真相也变了，两边错位。
- 反向指针（改被引用方时同步引用方）**不要依赖语义检索**：索引型工具在为「刚写完的内容」服务时有天然滞后。用 `read` 直接扫固定清单：
  - 常驻文件（已注入，零成本）
  - `memory/RECENT.md`、`memory/RECENT-archive.md`
  - `knowledge/00-索引.md`
- 替换知识条目时：旧条目保留并标 `status: 已替换于 YYYY-MM-DD → 继任者: <路径>`，读到该标记只准沿继任者前行，禁止引用旧内容。
- 承载面必须小而固定；指针散落到十几个文件时方案失效，先重估。

## 三、失败模式（真实踩过的）

1. **重复投递**：并发 check-then-act 竞态 → 发前先写去重键占位，发送失败回滚。
2. **未落盘就宣称完成**：先说「已记录」其实没写 → 永远先写文件再汇报。
3. **误列大目录烧 token**：找文件直接 `read` 目标；`list` 只剥到末级。
4. **摘要越滚越长**：没有硬上限的摘要一定只涨不跌 → 设 token 上限 + 双触发（时间优先、容量兜底）。
5. **归档成了坟场**：只写不读 → 记 `last-access`，超期标休眠，月度给人过目。
6. **超长上下文**：越拖越贵且容易超时 → 定期开新会话，开工只读摘要层。

## 四、审计模式（首次运行 / 大改之后）

- 逐字段对照**原始日记**取证，带上日期引用
- 现有内容一律当成「待验证假设」，没证据的字段降级或删除
- 防止棘轮：新增一条必须能指出是哪天的记录支撑的

## 五、别做的事

- 不为「某天没跑总结」补记
- 不把摘要放进每轮注入的文件
- 不为了「看起来在维护」而写空条目
- 不在摘要里复述细节（复述的那部分迟早错位）

## 六、交付给别人时（踩过的坑）

- **`.skill` 后缀不通用**：它只是 zip 改名，主流助手认的是 `skills/<名>/SKILL.md` 目录。交付用目录或 zip。
- **安装说明写在 SKILL.md 里**，不要另加 README（拿到包的人只读 SKILL.md）。
- **脚本路径用相对路径**，不要写死作者机器的绝对路径；目录不存在时自动建骨架。
- 交付前自己用空目录跑一遍（`cd /tmp && python3 <path>/scripts/xxx.py --dry-run`）——作者本人的环境永远不是验收环境。
